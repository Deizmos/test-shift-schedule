# План: график смен

Реализация тестового задания по [макету Figma](https://www.figma.com/design/QVdDSEGTL1bWg7UmuPpoPe). Стек: Vue 3, TypeScript, PHP / Laravel 13.

Laravel 11 не ставится: Composer блокирует весь ряд `laravel/framework` 11 из‑за security advisories. Каркас собран на Laravel 13 — это актуальная версия под PHP 8.5.

Критерий готовности каждого этапа — поведение из подписей кадров в Figma, а не только внешнее сходство.

## Цель

Одна страница «график смен»: таблица сотрудники × даты. Пользователь смотрит расписание, назначает и меняет смены, работает с шаблонами и сохраняет результат на сервер. Авторизации в макете нет — не делаем. Сотрудников и шаблоны кладём сидами.

## Поведение из макета

- Поиск по ФИО.
- Навигация по периоду.
- Переключение вида **неделя / месяц**.
- Клик по **цифре даты** — меню быстрого выбора смены.
- Клик по **ячейке** сотрудник × дата — выбор шаблона.
- Шаблоны **Утро / День / Вечер** с готовым началом и концом; шаблон можно назначать разным сотрудникам повторно.
- Блок **«Своя смена»**: выделить одну или несколько ячеек, указать время начала и окончания, применить ко всем выделенным. Время можно менять и назначать снова.
- **Drag-and-drop** шаблона смены между ячейками.
- Все способы пишут в одни данные, результат виден сразу, без перезагрузки страницы. Назначенные смены можно дальше редактировать.
- **Покрытие даты:** если на день есть хотя бы одна смена, индикатор голубой, иначе исходный. Обновляется при любом добавлении или удалении смены.

Визуальные состояния выделения, ввода времени, меню, ячеек, поиска, кнопок и бейджей — как в Figma.

## Архитектура

Один проект на Laravel 13 (проще выложить на alwaysdata). Vue 3 + TypeScript собирается Vite в `public/`. Frontend ходит в JSON API `/api`. Локально — SQLite, на alwaysdata можно переключить на MySQL.

```
Vue calendar  --REST JSON-->  Laravel API  -->  employees, shift_templates, shifts
```

Frontend: Composition API, Pinia (сетка, выделение ячеек, период, вид недели/месяца). Отдельный роутер не нужен: одна страница.

Компоненты кита из верхней части макета лежат в `resources/js/kit`: кнопки, бейдж, поиск, ячейка дня, чип смены, карточка шаблона, ячейка сотрудника, панель выделения. Страница кита открывается, пока нет сетки графика.

## Домен

### employees

- `id`
- `name` — ФИО
- `position` — должность, в макете у всех «агент»
- `weekly_hours` — норма часов, в макете 24
- `avatar_url` — URL или пусто, пока фото из макета не выгружены

### shift_templates

- `id`
- `name` — Утро / День / Вечер
- `start_time`
- `end_time`
- `color`

### shifts

- `id`
- `employee_id`
- `date`
- `start_time`
- `end_time`
- `template_id` — `null`, если смена своя

Ограничение: у сотрудника не больше одной смены на дату (при повторном назначении — замена).

## API

- `GET /api/employees`
- `GET /api/templates`
- `GET /api/shifts?from=&to=`
- `POST /api/shifts` — одиночное и массовое назначение (шаблон или своё время, список ячеек employee + date). Повтор на ту же ячейку заменяет смену.
- `PUT /api/shifts/{id}`
- `DELETE /api/shifts/{id}`
- `POST /api/shifts/{id}/transfer` — перенос на другую ячейку. Если там уже есть смена, она удаляется.

Перенос drag-and-drop на фронте вызывает `transfer`.

Покрытие дат фронт считает по загруженным сменам периода, отдельный endpoint не обязателен.
